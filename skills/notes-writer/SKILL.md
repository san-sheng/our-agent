# notes-writer —— NOTES/ 学习笔记格式规范

写学习笔记前阅读本规范。笔记是「这块代码在实践什么原理」的记录，
不是代码注释的搬运——每个设计取舍都要写「为什么」，不写「是什么」。

## 元数据块（文件头部，必须）

```markdown
# M2 学习笔记 —— 第 N 步：主题

> 日期：YYYY-MM-DD（生活日；跨午夜 git 提交按日期规则归前一天）
> 内容：改了什么文件、做了什么
> 状态：✅ 完成（代码 + 测试 N 绿 + 真实 API 冒烟）
> 对应书：ChX §小节
> 落点：DESIGN.md §9 的 M2 拆步「X」在此落实
```

## 章节结构（正文）

- `## 0. 一句话总结`：两三条要点，看的人 30 秒知道这步干了什么
- `## 1. 为什么需要`：书里的原理 + 我们的场景
- 中间章节：设计取舍、实现细节、踩坑——每项写「为什么」不写「是什么」
- `## N. 测试策略`：用例清单表（用例 | 验证点）
- `## N+1. 验证结果`：真实 API 冒烟输出记录（贴关键输出，标注 ✅/❌）
- `## 学习点自查`：checkbox 列表，对应「这一步应当能回答的问题」
- `## 下一步`：下一步做什么 + 已知遗留
- `## 附：文件清单`：改动的文件 + 一句话说明

## 验证结果记录规范

- 贴关键输出，不贴完整日志
- 每个验证点用 ✅ / ❌ 标注
- 数字写实（测试数量、行数、命中率），可复现

## 反例清单

- ❌ 不写「是什么」：语法解释、API 逐字段说明
- ❌ 不写流水账：改了什么文件列表不算笔记主体
- ❌ 不写「我看看」：验证必须附可复现证据
